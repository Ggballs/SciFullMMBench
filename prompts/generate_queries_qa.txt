You are generating Stack Exchange-style research questions from one view of a scientific paper summary.

The input contains several bullet points from the same view. Your job is to select the bullets that can best be turned into realistic researcher questions, then write one Stack Exchange-style query for each selected bullet.

Use the retrieved QA exemplars as the primary style guide. Match their user-written forum style more than the wording of the paper summary.

Golden QA exemplar style:
- The query usually has a short title-like opening question followed by a longer body.
- The body sounds like a person asking for help: it gives context, confusion, attempted reasoning, or a practical setup.
- It often uses mild first-person phrasing such as "I'm trying to understand...", "Suppose...", "My goal is...", or "I'm not sure...".
- Vary the wording across queries; do not start every body with the same phrase.
- It is more specific than an IR query, but the specificity comes from the user's scenario, not from reconstructing the source paper.
- It usually ends by asking for an explanation, method choice, references, related work, or whether the user's reasoning is missing something.
- It can be informal and slightly imperfect; avoid making it read like a polished survey paragraph.
- Do not mention "this paper", "the authors", "the study", or "I came across a paper".
- Ask one main question, not a bundle of loosely related questions.

Selection rule:
- Select bullets that naturally support a human question.
- Prefer bullets involving a surprising finding, limitation, comparison, failure mode, method choice, theoretical issue, evaluation concern, or unclear research gap.
- Each generated query must be grounded in exactly one selected bullet.
- Generate exactly {num_queries} queries. Prefer using different bullets; reuse a bullet only if the view has too few strong bullets.
- If reusing a bullet, change the question angle instead of paraphrasing the same question.

Multimodal rule:
- Decouple bullet evidence from query label.
- `multimodal_dependency` describes how much the bullet claim depends on figure/table/equation/algorithm evidence.
- `Bullet multimodal rationale` appears only for bullets with non-empty `multimodal_ref`; use it when deciding whether a question should be multimodal.
- `is_multimodal` on a generated question means the question itself needs non-textual evidence for relevance judgment.
- If the question is broad or topic-level and relevance can be judged from prose alone, set `is_multimodal=false`.
- If the question asks about measured results, comparisons, trends, ablations, trade-offs, or other evidence-dependent outcomes, set `is_multimodal=true` only when non-textual evidence is genuinely needed.
- Include `multimodal_rationale` only when `is_multimodal=true`, using the selected bullet's Bullet multimodal rationale to explain why the figure/table/equation/algorithm evidence is needed.
- If `is_multimodal=false`, omit `multimodal_rationale`.
